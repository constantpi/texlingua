# ビルダーの設定と契約

## 対応したい違い

論文のビルド方法は、TeX エンジンだけでは決まりません。
文書クラス、日本語対応パッケージ、文献ツール、索引生成、実行回数、latexmk の設定なども関係します。
そのため、エンジン名を一つ切り替えるだけでは既存のビルド環境を十分に再利用できません。

言語変換とファイル管理を `build.sh` が担当し、コンパイル全体を担当する
実行ファイル（ビルダー）を差し替えられます。

## 設定インターフェース

既存のコマンド形式 `./build.sh FILE.tex [ja|en|all]` を維持します。
ビルダー未指定または空文字の場合は、同梱の ptex2pdf / pbibtex の手順を使用します。
独自の手順は環境変数で実行ファイルを明示して選択します。

```bash
TEXLINGUA_BUILDER=./scripts/compile-paper.sh ./build.sh main.tex all
```

`TEXLINGUA_BUILDER` は単一の実行ファイルのパスとし、相対パスは `build.sh` を起動した時点の
作業ディレクトリを基準に解決します。引数付きのコマンド文字列にはしません。
必要なオプションや複数段階の処理は、指定したスクリプト内に記述します。
`eval`、設定ファイルの自動 `source`、エンジンの自動推測は使いません。
スクリプトには適切な shebang（例: `#!/usr/bin/env bash`）と実行権限が必要です。
`compile-paper.sh` のように `/` を含まない指定も起動時のディレクトリにあるファイルを指し、PATH 検索は行いません。
ファイル不存在・実行権限不足・ディレクトリ指定はビルド前にエラーにします。

専用の設定ファイル形式はありません。
プロジェクトで共有したい場合は、ビルダースクリプトをリポジトリに含めて呼び出し方を記載します。

## ビルダーの契約

`build.sh` が言語ごとのコピーと変換を終えた後、次の条件でビルダーを一回呼び出します。

| 項目 | 契約 |
|---|---|
| 作業ディレクトリ | `/tmp` 内の言語別コピーのルート |
| 第1引数 | エントリーファイルの相対パス（例: `./main.tex`） |
| 第2引数 | `default`、`ja`、`en` のいずれか。`all` は個別に二回呼ぶ |
| PDF | 作業ディレクトリ直下に `main.pdf` のように元の stem で生成する |
| 成功 | 必要な全工程が成功し、終了コード 0 を返す |
| 失敗 | 非ゼロ終了。既存の公開先 PDF は `build.sh` が保持する |
| 読み込み記録 | 可能なら作業ディレクトリ直下に `main.fls` を残す |
| 書き込み先 | 一時コピー内。元の原稿や最終 PDF 出力先を直接変更しない |

ビルダーはコンパイル、文献処理、必要な再実行をまとめて担当します。
言語の識別を引数に含めますが、日本語版と英語版で同じ手順を使うビルダーは第2引数を無視できます。
`main-ja.pdf` などへの命名と最終出力先への配置は、引き続き `build.sh` が担当します。

別の出力ディレクトリや jobname を使う既存レシピは、ビルダー側で成果物をこの契約に合わせて配置します。
外部ビルダーの内部処理を `build.sh` が解析したり、追加の BibTeX 処理を挟んだりすることはありません。
外部ビルダー使用時には、ptex2pdf / pbibtex は不要です。必要なツールの検査はビルダー側で行ってください。

## 既存の設定との関係

- ptex2pdf / pbibtex: 同梱の `scripts/build-ptex2pdf.sh` が標準の処理を担当します。
- latexmk: ビルダーから呼び出し、コピー内のプロジェクト用 `.latexmkrc` を利用します。
  エンジン、文献処理、再実行の制御は latexmk 側に任せます。
- 独自の複数段階ビルド: Makefile や既存のスクリプトをビルダーから呼び出せます。
  原稿のある絶対パスへ移動せず、一時コピーを対象として実行する必要があります。
- LaTeX Workshop: JSON のレシピを自動変換する機能は設けません。
  同じビルダースクリプトをエディターのレシピから呼び出すなど、コンパイル手順を共有できます。

ビルダーを替えても文書クラスやプリアンブルは変更しません。
たとえば同梱の `jsarticle` サンプルを別系統のエンジンへ移す場合、
文書側の対応も必要です。ビルド手順を変更できることと、文書のエンジン互換性は別に扱います。

## 日本語検出との関係

`.fls` があれば、コピー内で実際に読み込まれた `.tex` を検査します。
複数回実行するビルダーでは、各回の記録を連結した `.fls` を最終成果物として残すことで、
初回だけ読み込まれたファイルも検出対象に含められます。
最後の一回の `.fls` だけを残す場合は、その記録にあるファイルが検出対象となります。
`.fls` がない場合は、警告付きでコピー内の全 `.tex` を検査する現行の代替処理を維持します。

## 自動テスト

- ビルダー未指定時の既存テストが引き続き成功すること。
- 指定したビルダーだけが実行され、ptex2pdf / pbibtex が不要になること。
- 作業ディレクトリ、パスに空白がある場合の引数、言語引数が契約どおりであること。
- ビルダー不存在・実行権限不足・途中失敗・PDF 未生成をエラーにできること。
- `all` で片方が失敗しても他方を試み、既存 PDF を保持すること。
- `.fls` あり・なしの日本語検出と、一時領域の削除が機能すること。

これらは `python3 tests/test_build.py` で模擬ビルダーを使って検証します。
実際の組版と参照解決は、対応する TeX 環境で別途確認してください。
